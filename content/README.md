# Наполнение сайта

Эта папка — **единственный источник** основного наполнения «МоёПраво»: объектов защиты, статей,
чек-листов, памяток и их исходных файлов. Пользовательские данные (профили, избранное, история)
сюда не относятся и хранятся только в базе.

При каждом развёртывании и в CI бэкенд синхронизирует базу с этой папкой:

```bash
cd backend
npm run db:migrate   # схема
npm run db:seed      # наполнение из content/
```

Синхронизация приводит базу в точное соответствие папке: новые и изменённые записи сохраняются,
а записи, которых здесь больше нет, **снимаются с публикации** — из базы они не удаляются. Перед
записью всё наполнение проверяется; при любой ошибке синхронизация останавливается, а база
остаётся прежней.

## Файлы

| Файл | Содержимое |
| --- | --- |
| `objects.json` | Объекты защиты (программный код, бренд, базы данных…) в порядке показа на сайте |
| `materials.json` | Статьи, чек-листы и памятки в порядке показа в каталоге |
| `files/` | Исходные DOCX. Сайт отдаёт их через `GET /api/materials/:id/file` |

## Объект защиты

```json
{ "id": "code", "title": "Программный код", "description": "…", "published": true }
```

## Материал

```json
{
  "id": "checklist",
  "topic": "code",
  "kind": "checklist",
  "title": "Чек-лист: Защитить программный код",
  "pageTitle": "Защита программного кода",
  "description": "8 шагов · от фиксации до требований",
  "file": { "path": "checklist.docx", "name": "Чек-лист программный год - защита прав.docx" },
  "related": ["code-0", "code-1", "code-expert"],
  "intro": [],
  "sections": [{ "id": "step-1", "title": "…", "toc": "Зафиксировать нарушение", "blocks": [] }]
}
```

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | да | Постоянный идентификатор: латиница в нижнем регистре, цифры и `-` |
| `topic` | да | `id` объекта из `objects.json` |
| `kind` | да | `article` (статья), `checklist` (чек-лист) или `reference` (памятка) |
| `title`, `description` | да | Название и подпись в карточках и каталоге |
| `pageTitle` | нет | Заголовок страницы материала; по умолчанию `title` |
| `file` | нет | `path` — имя файла в `files/`, `name` — имя файла при скачивании |
| `related` | нет | `id` связанных материалов в порядке показа |
| `intro`, `sections` | нет | Текст материала: вступление и разделы (шаги чек-листа) из блоков |
| `published` | нет | `false` скрывает материал, не удаляя его из папки |

Материал без `intro` и `sections` считается анонсом: он виден в каталоге, но открывается
карточкой «полный текст пока не опубликован».

Блоки текста: `paragraph`, `heading`, `note` (с `runs`), `list` (`ordered`, `items`), `table` (`rows`,
первая строка — заголовки), `action` (`text`, `action`). Фрагменты `runs` — это `{ "text" }` с
необязательными `bold`, `italic`, `href` (ссылка на страницу сайта `/…` или внешний `https://…`) и
`action` (открыть диалог, например `definition:presumption`). Типы описаны в `docs/api.md`.

## Правила

1. **`id` после публикации не меняется.** На него ссылаются избранное пользователей, история,
   связи между материалами и адреса страниц. Для базы новый `id` — это другой материал: старый
   снимется с публикации, а избранное на него пропадёт с сайта.
2. **Убрать материал с сайта** — удалить его из `materials.json` или поставить `"published": false`.
   Записи в избранном у пользователей сохранятся и вернутся, если материал опубликовать снова.
3. Опубликованный материал не может относиться к неопубликованному объекту защиты.
4. Ссылки в `related` должны указывать на существующие материалы, файлы из `file.path` — лежать в `files/`.
5. После правки запустите `npm run db:seed` в `backend/` — проверка сразу покажет ошибки. CI делает
   то же самое при каждом изменении этой папки.
