# Наполнение сайта

Эта папка — **единственный источник** основного наполнения «МоёПраво»: объектов защиты, статей,
чек-листов, памяток и их исходных файлов. Пользовательские данные (профили, избранное, история)
сюда не относятся и хранятся только в базе.

При каждом развёртывании и в CI бэкенд синхронизирует базу с этой папкой:

```bash
cd backend
npm run db:migrate   # схема
npm run db:seed      # наполнение из content/
```

Синхронизация приводит базу в точное соответствие папке: новые и изменённые записи сохраняются,
а записи, которых здесь больше нет, **снимаются с публикации** — из базы они не удаляются. Перед
записью всё наполнение проверяется; при любой ошибке синхронизация останавливается, а база
остаётся прежней.

## Файлы

| Файл | Содержимое |
| --- | --- |
| `objects.json` | Объекты защиты (программный код, бренд, базы данных…) в порядке показа на сайте |
| `materials.json` | Статьи, чек-листы и памятки в порядке показа в каталоге |
| `files/` | Исходные DOCX. Сайт отдаёт их через `GET /api/materials/:id/file` |
| `fees/` | Суммы и формулы калькулятора пошлин — см. раздел [«Пошлины»](#пошлины) |
| `templates/` | Шаблон конструктора `code-claim.json` и исходный DOCX; заполненные пользователями документы здесь не хранятся |

## Объект защиты

```json
{ "id": "code", "title": "Программный код", "description": "…", "published": true }
```

## Материал

Общие чек-листы с `topic: null` служат входом в три сценария: `ownership-overview`
(`/ownership`), `protect-overview` (`/protect`) и `defend-overview` (`/defend`).
После вводного чек-листа пользователь переходит к объекту по ссылкам в тексте;
в разделах защиты и оспаривания также есть блок выбора всех объектов в конце.
Исходники новых чек-листов сохранены без изменений в `files/protect-overview.docx`
и `files/defend-overview.docx`. На сайте исправлены пробелы и нумерация шагов
оспаривания (в исходнике после шага 4 идёт шаг 6). Заглушки `[ссылка]` заменены
на маршруты существующих тематических разделов, отсутствующие темы отмечены
как готовящиеся. Объект литературных произведений в меню не возвращается.

```json
{
  "id": "checklist",
  "topic": "code",
  "kind": "checklist",
  "title": "Защитить программный код",
  "pageTitle": "Защитить программный код",
  "description": "8 шагов · от фиксации до требований",
  "file": { "path": "checklist.docx", "name": "Чек-лист программный код - защита прав.docx" },
  "related": ["code-0", "code-1", "code-expert"],
  "intro": [],
  "sections": [{ "id": "step-1", "title": "…", "toc": "Зафиксировать нарушение", "blocks": [] }]
}
```

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | да | Постоянный идентификатор: латиница в нижнем регистре, цифры и `-` |
| `topic` | да | `id` объекта из `objects.json` или `null` для общего материала, охватывающего несколько объектов |
| `kind` | да | `article` (статья), `checklist` (чек-лист) или `reference` (памятка) |
| `title`, `description` | да | Название и подпись в карточках и каталоге |
| `pageTitle` | нет | Заголовок страницы материала; по умолчанию `title` |
| `file` | нет | `path` — имя файла в `files/`, `name` — имя файла при скачивании |
| `related` | нет | `id` связанных материалов в порядке показа |
| `intro`, `sections` | нет | Текст материала: вступление и разделы (шаги чек-листа) из блоков |
| `published` | нет | `false` скрывает материал, не удаляя его из папки |

Материал без `intro` и `sections` считается анонсом: он виден в каталоге, но открывается
карточкой «полный текст пока не опубликован».

Блоки текста: `paragraph`, `heading`, `note` (с `runs`), `list` (`ordered`, `items`), `table` (`rows`,
первая строка — заголовки), `action` (`text`, `action`). Фрагменты `runs` — это `{ "text" }` с
необязательными `bold`, `italic`, `href` (ссылка на страницу сайта `/…` или внешний `https://…`) и
`action` (открыть диалог, например `definition:presumption`). Типы описаны в `docs/api.md`.

## Правила

1. **`id` после публикации не меняется.** На него ссылаются избранное пользователей, история,
   связи между материалами и адреса страниц. Для базы новый `id` — это другой материал: старый
   снимется с публикации, а избранное на него пропадёт с сайта.
2. **Убрать материал с сайта** — удалить его из `materials.json` или поставить `"published": false`.
   Записи в избранном у пользователей сохранятся и вернутся, если материал опубликовать снова.
3. Опубликованный материал не может относиться к неопубликованному объекту защиты.
4. Ссылки в `related` должны указывать на существующие материалы, файлы из `file.path` — лежать в `files/`.
5. После правки запустите `npm run db:seed` в `backend/` — проверка сразу покажет ошибки. CI делает
   то же самое при каждом изменении этой папки.

## Пошлины

Данные калькулятора пошлин на сайте (`/tools/calculator`) лежат в папке `fees/` — по одному файлу
на вид объекта. Суммы считает сервер по этим файлам; программировать ничего не нужно.

| Файл | Что внутри | Основание |
| --- | --- | --- |
| `fees/trademarks.yaml` | 42 пошлины за действия с товарными знаками | Положение о пошлинах (ПП РФ № 941), прил. № 1, раздел 2 |
| `fees/programs.yaml` | 4 пошлины за регистрацию программ для ЭВМ и баз данных | ст. 333.30 НК РФ |

Файлы в формате YAML: текст с отступами, без скобок и запятых, комментарии начинаются с `#`.

### Как устроена пошлина

```yaml
  - пункт: "2.4"
    раздел: Подача заявки и экспертиза
    название: Экспертиза обозначения, заявленного в качестве товарного знака
    формулировка: >-
      Проведение экспертизы обозначения, заявленного в качестве товарного знака, и принятие
      решения по ее результатам
    сумма: 13 000
    доплаты:
      - за: каждый класс МКТУ сверх первого
        параметр: классы
        сверх: 1
        сумма: 2 500
      - за: каждый товар или услугу сверх десяти в одном классе
        параметр: товары_в_классе
        сверх: 10
        сумма: 500
    примеры:
      - { классы: 3, товары_в_классе: [15, 10, 4], итог: 20 500 }
```

| Поле | Что писать |
| --- | --- |
| `пункт` | Номер пункта в нормативном акте, в кавычках: `"2.4"` |
| `раздел` | Группа в списке действий на сайте |
| `название` | Короткое название действия для сайта |
| `формулировка` | Дословный текст пункта (после `>-` с новой строки, с отступом); показывается пользователю |
| `сумма` | Основная пошлина в рублях; можно с пробелами: `13 000`. Если пошлина только за единицы — `0` |
| `доплаты` | Необязательно. Каждая доплата: `за` (текст для сайта), `параметр`, `сверх` (сколько единиц бесплатно, по умолчанию 0), `сумма` за единицу |
| `примеры` | Необязательно, но очень желательно: контрольные расчёты. Если формула даёт другую сумму, файл не будет принят |

**Как считается доплата:** количество единиц параметра сверх порога × сумма. Например, 7 классов при
`сверх: 5, сумма: 2 000` — это 2 × 2 000 = 4 000 ₽. Для параметра «да или нет» (бумажное
свидетельство) доплата добавляется один раз, если ответ «да»; `сверх` для него не пишется.
Для параметра «по классам» (товары в каждом классе) единицы считаются по каждому классу отдельно и
складываются.

### Поля в начале файла

| Поле | Что писать |
| --- | --- |
| `название` | Название вкладки калькулятора |
| `порядок` | Место вкладки: 1, 2, … |
| `основание` | Нормативный акт и редакция, из которых взяты суммы; показывается под результатом |
| `действует_с` | Дата вступления редакции в силу: `ГГГГ-ММ-ДД`, например `2025-10-04` |
| `ссылка_на_пункт` | Как называть пункт на сайте; вместо `{пункт}` подставится номер |
| `проверил` | ФИО юриста и дата сверки. Пока поле пустое, сайт не пишет, что суммы сверены |
| `примечание` | Необязательно: важная оговорка, показывается под результатом |
| `параметры` | Вопросы калькулятора: `вопрос`, `тип` (`число` с `от`/`до`, `да_нет`, `по_классам` с `от`/`до`) |

Параметр типа `по_классам` спрашивает число для каждого класса, поэтому рядом всегда должен быть
параметр `классы`.

### Как внести изменение

1. Открыть файл на GitHub, нажать ✏️, изменить суммы или тексты.
2. Обновить `действует_с`, `основание` (новая редакция акта) и `проверил`.
3. Поправить `примеры` под новые суммы — это проверка, что формула записана верно.
4. Сохранить как Pull Request. CI проверит файл; при ошибке в отчёте будет сказано по-русски, где
   она: например, «пункт «2.11»: «сумма» должна быть целым числом рублей, сейчас: «18 ооо» (буква
   вместо цифры?)».

Локально то же самое проверяет `npm run db:seed` в `backend/`.

**Частые ошибки YAML:**

- Двоеточие с пробелом внутри текста — значение нужно взять в кавычки:
  `название: "Изменение заявки: передача права"`. Внутри `формулировка: >-` кавычки не нужны.
- Отступы — только пробелами и одинаковые у всех полей одной пошлины.
- Пошлину нельзя удалить, просто стерев строку `- пункт:` — удаляйте весь блок до следующей пошлины.

Если в акте появилась пошлина, которую нельзя записать как «сумма + доплаты за единицы сверх порога»
(например, процент или зависимость от года), нужна доработка калькулятора — обратитесь к разработчику.
