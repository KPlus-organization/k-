# Frontend

**Точка входа во фронтенд — эта папка (`frontend/`).** Здесь размещается весь код клиентской части.
Стек (фреймворк, сборщик) выбирает фронтенд-разработчик. Каркаса пока нет.

## Договорённости с бэкендом

- Фронтенд — самостоятельный npm-проект: собственные `frontend/package.json` и `package-lock.json`,
  зависимости ставятся командой `npm install` внутри `frontend/`. От `backend/` он не зависит.
- Dev-сервер фронтенда по умолчанию работает на **`http://localhost:3000`**: этот origin бэкенд
  разрешает в CORS. Если сборщик использует другой порт (например, Vite — `5173`), есть два варианта:
  настроить порт `3000` в конфиге сборщика или поменять `FRONTEND_ORIGIN` в `backend/.env`.
- Адрес API в разработке — **`http://localhost:3001`**. Не вшивайте его в код, а берите из переменной
  окружения сборщика (например, `VITE_API_URL` или `NEXT_PUBLIC_API_URL`).
- Эндпоинты, формат ошибок и HTTP-статусы описаны в [../docs/api.md](../docs/api.md).
  Пока там только технические эндпоинты. Для бизнес-данных используйте моки до согласования API.
- Добавьте в `.gitignore` специфичные для стека артефакты сборки. Общие `node_modules/`, `dist/`,
  `.env`, `.env.*` уже игнорируются корневым `.gitignore`.

## Запуск вместе с бэкендом

```bash
# терминал 1
cd backend && npm run dev     # API на http://localhost:3001

# терминал 2
cd frontend && npm run dev    # после того как фронтенд-проект будет создан
```

Когда фронтенд-проект будет создан, допишите в этот файл, как его установить и запустить,
а также где лежит его главный модуль (например, `src/main.tsx`).
