# МоёПраво — frontend

Интерактивный прототип по [макету Figma](https://www.figma.com/design/rPVIDMRNeBzbx2TPrxJtOq/Untitled).
React + TypeScript + Vite. Данные моковые; для работы интерфейса бэкенд и PostgreSQL не нужны.

## Запуск

Требуется Node.js 24+.

```powershell
cd 'C:\Program Files\programms\k-\frontend'
npm install
npm run dev
```

Открыть **http://localhost:3000**. Порт соответствует `FRONTEND_ORIGIN` существующего бэкенда.
Зависимости зафиксированы в `package-lock.json`; для чистой установки можно использовать `npm ci`.

## Экраны и сценарии

| Адрес                  | Содержимое                                                                      |
| ---------------------- | ------------------------------------------------------------------------------- |
| `/`                    | Главная, четыре равные карточки направлений и пять инструментов                 |
| Кнопка меню в шапке    | Боковая навигация из Figma, закрытие по Escape и клику вне меню                 |
| `/protect`             | Семь объектов защиты; доступен только программный код, остальные пока не готовы |
| `/defend`              | Объекты для оспаривания претензии; разделы пока не готовы                       |
| `/protect/code`        | Восемь шагов защиты кода из DOCX, навигация и избранное                         |
| `/protect/brand`       | Статья и чек-лист по защите обозначений бренда                                  |
| `/protect/databases`   | Материалы об оформлении прав и защите авторства на базу данных                  |
| `/ownership`           | Раздел оформления прав, переход к базе данных                                   |
| `/ownership/databases` | Пять шагов оформления прав на базу данных                                       |
| `/articles/:id`        | Полные тексты статей, памятки и чек-листы из документов                         |
| `/login`               | Демо-вход, показ пароля, переход к регистрации                                  |
| `/register`            | Валидация email, пароля, повторного пароля и согласия                           |
| `/profile`             | Личный кабинет, редактирование профиля, избранное и моковая история             |
| `/articles`            | Дополнительный каталог материалов в стиле макета, фильтрация по теме            |
| `/search?q=код`        | Поиск по локальным материалам и объектам защиты, состояние без результатов      |

В шапке работает поиск и сочетание Ctrl+K / Cmd+K. Интерфейс адаптирован для мобильного экрана.
На главной карточка «Оформить права» временно отключена и ничего не открывает.
Описание каждого объекта в `/protect` и `/defend` скрыто под i: оно открывается при наведении,
фокусе клавиатуры или касании, закрывается по Escape. Литературные произведения исключены
из списка объектов, бокового меню и фильтров. Ранее добавленные материалы по бренду и базам
данных доступны через каталог статей; ограничение готовности относится к списку `/protect`.

Для демо-входа укажите любой непустой логин и пароль от 8 символов: откроется профиль Анны из макета
или ранее созданный локальный профиль. Можно также открыть `/profile` и нажать «Открыть демо-профиль».
Регистрация и вход не создают серверную сессию и не обеспечивают аутентификацию.

Имя, логин, email и избранное хранятся в `localStorage` с префиксом `moe-pravo:`.
Пароли не сохраняются и не отправляются. При недоступном хранилище интерфейс работает в памяти.
История навигации — статичные данные из макета. Для сброса демо удалите ключи с этим префиксом
в хранилище сайта через инструменты разработчика браузера.

Калькулятор, конструктор документов, проверка товарного знака, каталог юристов и оценка рисков
пока показывают диалоги «раздел готовится». Реальные расчёты, генерация
юридических документов, отправка писем и подбор специалистов не имитируются.

## Материалы из DOCX

Семь предоставленных документов преобразованы в восемь материалов. Объединённый файл про бренд
разделён на статью и чек-лист, связанные друг с другом. Тексты хранятся в
`src/entities/material/model/materials.json`; типы, подписи и индекс полнотекстового поиска — в
`materials.ts`. Исходные файлы сохранены без изменений в `public/materials/` и доступны для скачивания.

| Объект          | Материал                                            | Маршрут                         |
| --------------- | --------------------------------------------------- | ------------------------------- |
| Бренд           | Элементный состав бренда в IT-среде                 | `/articles/brand-article`       |
| Бренд           | Порядок защиты бренда и домена, 4 шага              | `/articles/brand-protection`    |
| Базы данных     | Закрепление прав и регистрация, 5 шагов             | `/ownership/databases`          |
| Базы данных     | Фиксация авторства и доказательства, 7 шагов        | `/articles/database-protection` |
| Программный код | Защита нарушенных прав, 8 шагов                     | `/protect/code`                 |
| Программный код | Как доказывают заимствование кода                   | `/articles/code-0`              |
| Программный код | Запрет использования, убытки или компенсация        | `/articles/code-1`              |
| Программный код | Вопросы эксперту компьютерно-технической экспертизы | `/articles/code-expert`         |

Сохранены таблицы, списки, выделения и внешние ссылки из документов. Редакторские указания
о ссылках и всплывающих пояснениях заменены переходами, пояснениями и диалогом термина.
Пустые декоративные рамки из Word не перенесены. Юридическое содержание перенесено из
предоставленных текстов; самостоятельная проверка норм, сумм и сроков в эту задачу не входила.
Три старые карточки из Figma о регистрации товарного знака остаются с пометкой об отсутствии
полного текста, поскольку среди предоставленных файлов этих статей нет.

Чек-листы предназначены для чтения: отметок выполнения и учёта прогресса нет.
Оглавление позволяет перейти к нужному шагу, материал можно сохранить в избранное.
Связанные статьи открываются из шагов и боковой колонки; все материалы доступны в каталоге,
фильтруются по объекту и находятся по полному тексту.

## Архитектура и стили

Проект организован по [Feature-Sliced Design](https://feature-sliced.design/docs/get-started/overview):

```text
src/
  app/         # точка входа, сборка приложения, маршруты, глобальные стили
  pages/       # home, auth, profile, protection, object-materials, material, articles, search
  widgets/     # шапка, подвал, заголовки страниц, юридическая оговорка, диалоги
  features/    # session, favorites, search, profile-settings
  entities/    # material (каталог и чек-лист), profile (профиль и моки)
  shared/      # переиспользуемый UI, хранилище, утилиты, конфигурация
```

Срезы экспортируют публичный API через `index.ts`. Внешние импорты используют алиас `@/`
и этот API, например `import { useFavorites } from '@/features/favorites'`.
Внутри среза используются относительные импорты. ESLint проверяет направление зависимостей:
`app → pages → widgets → features → entities → shared`, запрещает импорты между соседними
срезами и доступ к внутренним файлам другого среза. В Shared разрешены связи между сегментами.
Проверки действуют и для относительных путей, а не только для алиаса.

Стили используют **Tailwind CSS 4 + CSS Modules + normalize.css**. Tailwind подключён через
`@tailwindcss/vite`. `app/entrypoint.tsx` загружает локальный Inter и `app/styles/tailwind.css`:
этот файл задаёт порядок слоёв и подключает `normalize.css` и `base.css` в слой `base`.
Preflight отключён, чтобы не дублировать нормализацию и сохранить оформление макета.
В `base.css` находятся настройки документа, типографика и CSS-переменные цветов.

Для сеток, отступов и простых стилей используем utility-классы Tailwind, например
`grid gap-4.5`, `mt-2`, `text-brand`. Адаптивная сетка статей, результаты поиска и форма
настроек уже используют их. Тема в `tailwind.css` связывает `brand`, `ink`, `muted`, `line`,
`mint`, `surface` с существующими CSS-переменными; цвета в обоих подходах имеют один источник.
Tailwind сканирует только `src`; имена utility-классов пишем целиком, без динамической сборки.

Сложное оформление компонентов и экранов остаётся в `*.module.css` рядом с UI. Общие визуальные
классы экспортируются как `ui` из `@/shared/ui`; `cx` из `@/shared/lib` объединяет имена классов:
`cx(ui['button'], ui['primary'], 'mt-2')`. Модули находятся вне CSS-слоёв и имеют приоритет
над utilities: не задаём одно свойство одновременно модулем и Tailwind на одном элементе.
Для изменения внешнего вида вложенного компонента передаётся `className`.
При использовании границ без Preflight явно задаём стиль, например `border border-solid border-line`.
Настройка соответствует [официальной инструкции без Preflight](https://tailwindcss.com/docs/preflight#disabling-preflight).

Исходные тексты Figma хранятся в `entities/material/model/design.json`, моковый профиль — в
`entities/profile/model/profile.ts`. Изображения находятся в `public/images/`.
Общие операции браузерного хранилища вынесены в `shared/lib`, пользовательские сценарии — в features.

Токен Figma лежит только в корневом `.env.figma.local`, который исключён из Git.
Фронтенд его не читает; токен не нужен для запуска и не входит в сборку.
Не добавляйте токены в переменные с префиксом `VITE_`.

## Проверки и сборка

```powershell
npm run check
npm run build
npm test
npm run preview
```

`check` выполняет ESLint (TypeScript, React Hooks, доступность и границы FSD), Stylelint
(стандартный CSS, CSS Modules и директиву темы Tailwind), проверку форматирования Prettier, проверку типов и пять
тестов архитектурных ограничений. Ошибки и предупреждения линтеров блокируют проверку.

Отдельные команды: `lint`, `lint:js`, `lint:css`, `typecheck`, `test:architecture`, `format:check`.
Для автоматических исправлений используйте `npm run lint:fix` и `npm run format`.
Конфигурации: `eslint.config.js`, `stylelint.config.js`, `.prettierrc.json`.
`prettier-plugin-tailwindcss` сортирует utility-классы в `className` и вызовах `cx`, учитывая тему проекта.
TypeScript закреплён на ветке 6.0: установленный `typescript-eslint` поддерживает версии ниже 6.1.
ESLint 9 выбран для совместимости с `eslint-plugin-jsx-a11y`.

`build` проверяет типы и создаёт `dist/`. `preview` обслуживает собранный сайт на порту 3000.
Для размещения на статическом хостинге нужен fallback всех маршрутов на `index.html`.

Браузерные тесты используют установленный Google Chrome (`channel: 'chrome'`) и запускают dev-сервер
автоматически. Если Chrome нет, установите его либо настройте Playwright на Chromium. Снимки всех
экранов сохраняются в `../tmp/preview/`; временные результаты исключены из Git.
В CI используется Chromium. Workflow `../.github/workflows/frontend.yml` устанавливает зависимости,
выполняет `check`, сборку и браузерные тесты при push/PR с изменениями фронтенда.
Браузерные проверки используют доступные роли и `data-testid`, а не сгенерированные имена CSS-классов.

## Подключение бэкенда в дальнейшем

Текущий API описан в [../docs/api.md](../docs/api.md): доступны только `GET /` и `GET /api/health`.
Бизнес-эндпоинтов, регистрации, авторизации и модели предметных данных пока нет.
Перед интеграцией согласуйте контракты в `docs/api.md`, затем замените локальные моки запросами.
Адрес API следует задавать переменной окружения (например, `VITE_API_URL=http://localhost:3001`),
сохраняя существующий формат ошибок `{ error: { code, message } }`.
